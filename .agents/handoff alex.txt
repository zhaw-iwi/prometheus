What changed

- CR-01, 3627bfc: recorded the observed workflow failures and extended the isolated
  local-database and paid-provider acceptance harness.
- CR-02, 7793826: authoritative state queries, explicit return to Conversation,
  and same-task restart. Return preserves history/outcomes; ambiguous "start over"
  requests clarify intent. STOP no longer replaces an already terminal outcome.
- CR-03, 0b9c5f6: preparation and acceptance are distinct and explained. Ready means
  awaiting acceptance. Sensor execution requires acceptance followed by a fresh cue.
- CR-04, 4eb2047: content/style revisions preserve unchanged triggers, recognition
  settings, roles, limits and other protected terms. Preparation and acceptance
  must be renewed. Storage values were widened to 8192 characters; Live startup
  also waits for the provider's session.started event.
- CR-05, a3b3947: a bounded two-second Coordination input window handles measured
  short hesitations without interpreting each fragment as a separate task update.
- CR-06, 61ddf13: speaking occasions are tied to committed task authority and the
  current session/revision. Proposal, arming and contribution have distinct duties.
- CR-07, c663ca6: final spoken Live contributions enter Finishing until associated
  speech and scoped client playback confirmation arrive. Timeout, incomplete
  capture or lost ownership produces uncertainty, without automatic replay.
- CR-08, 738501a: bounded content-free transition telemetry and clearer activity
  feedback explain acceptance, waiting, finishing, reflection and uncertainty.
  Capture/teardown diagnostics remain conservative about causes.
- CR-09, 86fc501: combined journeys and rollout documentation. Acceptance exposed
  additional fixes: current perception is evaluated at execution; committed speech
  supplies the current Live contribution reference; arming defers unsolicited
  sensory context; response association can skip one verified unrelated capture
  within the original deadline. Eligible exact literals can match without another
  model call, while still requiring scoped playback confirmation.

The existing state machine, Storage, task engine and event history remain the
